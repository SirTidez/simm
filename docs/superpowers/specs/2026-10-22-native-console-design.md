# Native console integration

The user requested product integration of the approved docked-console experiment: preserve Steam launching and game independence, retain native console interaction, display configurable profile/mod/game details, and provide Close Game in the sidebar.

After user review, use an Environment Status workspace inside the main Tauri window. Its left pane is occupied by the actual unowned top-level Windows console; its right pane is a themed, constrained and scrollable details inspector with a fixed Close Game action. Report the DOM pane bounds to the controller and hide the native pane when navigating away or showing an overlapping dialog. Persist automatic opening, section visibility, path visibility and sidebar width in SQLite app_meta. Show process timing, game details, active profile and installed/enabled inventory with concise labels, file names and available version/author metadata, without claiming runtime-loaded module data. No telemetry opt-in or injected game plugin is required.

Keep the existing launch command and Steam options unchanged. After successful dispatch, open the console when enabled. Discovery waits for the matching executable path, binds PID plus creation time, and waits for an attachable native console. A missing/hidden console is a nonmodal state with retry; it does not mark game launch failed. Manual Open Console is available from environment actions.

Run docking in an independent mode of the installed SIMM executable, before normal CLI/single-instance startup. Start an independent recovery guard before changing console styles. Both validate process and window identities; neither reparents or assigns window ownership. Follow client geometry, ordinary Z order and minimize/restore. Restore bounds/styles/visibility and clear native selection on window close, application exit, controller loss or game exit. No fixed-duration test leases in product sessions. Recovery observes process/window loss, not console-I/O delays or a short inactivity timer. Keep helper state in a unique temporary directory. Normal shutdown waits briefly for restore; a forced host exit is recovered independently.

Close Game is explicit and confirmed inline in the sidebar so its confirmation cannot be obscured by the native pane. Revalidate the exact observed process, clear selection, and post WM_CLOSE to that process's Unity window. Never terminate a process automatically. If no Unity window is available, report the failure. Keep the session open until process exit is observed. Closing Console or SIMM never calls Close Game.

Windows alone supports docking. Other platforms return an explicit unsupported capability and retain their current launch behavior. Native selection can block a synchronous console writer, but is not a whole-process pause. Seamless startup hiding and structured logger/telemetry integration are outside this change.

Validation: full AGENTS.md frontend/Rust sequence; meaningful tests for preferences/contracts, sidebar controls and helper identity/recovery; disposable console lifecycle tests before live Steam tests; actual Tauri screenshots; common desktop viewport checks. Preserve prior dirty files. No publication or commit requested.
