# Tailwind v4 shadcn Base Nova Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Tailwind CSS v4 and shadcn/ui `base-nova` to SIMM so new and touched UI can use maintainable semantic components without forcing a risky full rewrite.

**Architecture:** Bootstrap Tailwind and shadcn alongside the existing CSS, then migrate one visible surface at a time. Keep `src/style.css` as the global stylesheet at first so current app chrome, theme variables, and Tauri-specific layout rules remain intact while shadcn tokens are introduced.

**Tech Stack:** Bun, Vite, React 18, Tauri 2, Tailwind CSS v4, `@tailwindcss/vite`, shadcn/ui `base-nova`, lucide icons, Vitest, TypeScript.

**Current checkpoint:** Tailwind v4, shadcn `base-nova`, foundation components, and SIMM primitives are merged into `0.8.5`. Setup Tasks 1-6 are complete, and the first broad atom pass has reached `DownloadsPanel`, the shared security report view, `ConfigurationOverlay`, `LogsOverlay`, `Settings`, the App shell, `ModsOverlay`, and `ModLibraryOverlay`. A `vendor-ui` manual chunk now isolates Base UI/shadcn runtime cost so small lazy surfaces do not absorb the full dependency payload. Task 9 is the current conversion backlog. The dead `legacyLayout` scaffolding has been removed from `ModsOverlay` and `ModLibraryOverlay`; `ModsOverlay` no longer appears in the raw-control inventory, and `ModLibraryOverlay` has one remaining active raw button.

**Current docs refresh:** Context7 checked shadcn/ui and Tailwind CSS docs on 2026-05-09. Current shadcn guidance still treats generated components as source-owned project code configured by `components.json` and added with `shadcn@latest add <component>`. Current Tailwind v4 guidance for Vite still uses `@tailwindcss/vite` in `vite.config.ts` and `@import "tailwindcss";` in the app CSS. The active repo matches this shape: `bunx --bun shadcn@latest info --json` reports Vite, TypeScript, Tailwind v4, `base-nova`, `base`, lucide, `src/style.css`, and generated UI components including `alert-dialog`, `alert`, `button`, `checkbox`, `context-menu`, `dialog`, `dropdown-menu`, `empty`, `field`, `input`, `label`, `popover`, `progress`, `radio-group`, `scroll-area`, `select`, `separator`, `skeleton`, `switch`, `tabs`, `textarea`, and `tooltip`.

## Constraints

- Use `bun`, `bun add`, and `bunx --bun`; do not use npm or pnpm.
- Keep Cargo output in the default repository `target/`; do not use `CARGO_TARGET_DIR`.
- Preserve SIMM's existing desktop utility direction from `docs/simm-desktop-ui-redesign-spec.md`.
- Do not rewrite the app shell, Mod Library, or overlays as a new visual identity.
- Keep FontAwesome available during migration; lucide can become the default for new shadcn components, but replacing all existing icons is a separate task.
- Treat shadcn components as source code owned by this repo after generation. Review generated files before using them.
- Every phase must pass the frontend CI sequence before moving on:

```powershell
bun install
bunx tsc --noEmit
bun run lint
bun run test
bun run build
```

## File Structure

- Modify `package.json`: add Tailwind v4, shadcn support dependencies, and optional shadcn helper scripts.
- Modify `bun.lock`: generated by `bun install` / `bun add`.
- Modify `vite.config.ts`: add `@tailwindcss/vite` and `@` alias while preserving Tauri `base`, port, env, and build target behavior.
- Modify `tsconfig.json`: add `baseUrl` and `paths` for `@/*`.
- Modify `src/style.css`: add Tailwind import and shadcn CSS variables without deleting existing SIMM CSS.
- Create `components.json`: configure `base-nova`, Tailwind v4 CSS file, TypeScript, aliases, and lucide.
- Create `src/lib/utils.ts`: shadcn `cn()` helper.
- Create `src/components/ui/*`: generated shadcn components only as they are adopted.
- Create `src/components/primitives/*`: optional SIMM adapter components such as `SimmButton` only when needed to bridge old class names and new shadcn primitives.
- Modify tests next to each migrated surface, not as a broad snapshot rewrite.

## Regression Controls

- Do not migrate `ModLibraryOverlay.tsx` first; it is large and behavior-heavy.
- Do not replace app-wide layout classes and shadcn components in the same commit.
- Do not delete FontAwesome until every existing icon path has a tested lucide equivalent.
- Do not migrate dead `legacyLayout` blocks. Delete dead layout scaffolding after confirming tests cover the live workspace UI.
- Do not use `shadcn add --all`; the repo already has a broad generated set and remaining work is usage migration, not component discovery.
- Do not rely on Vite build alone; `bunx tsc --noEmit` is the first CI failure point.
- If a full Rust validation is needed because frontend/backend contracts changed, run:

```powershell
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
```

Known prior context: full Rust tests may have unrelated `services::mods` Windows symlink/privilege failures. Focused frontend migration should not block on unrelated pre-existing Rust failures unless the changed surface touches a Tauri contract.
